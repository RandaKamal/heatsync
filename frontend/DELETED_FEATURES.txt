DELETED / NOT-YET-BACKED-BY-BACKEND FEATURES
=============================================
Recorded when cleaning the 3-D scene to use only backend-provided data.
"Backend" = Flask API at /api/* as defined in backend/api/routes.py.

── REMOVED INTERACTIONS ─────────────────────────────────────────────────────
- OrbitControls  (drag to rotate, scroll to zoom, shift+drag to pan)
- Tap a device   (click → DeviceCard popup / device selection)
- Device inspect panel opened from 3-D click (DeviceCard)
- Hover cursor change (pointer cursor on hover over devices and rooms)
- scene-instructions HUD ("Drag rotate / Scroll zoom / Shift+drag pan / Tap a device inspect")

── STATISTICS REMOVED FROM 3-D LABELS (not provided by backend) ─────────────
- efficiencyCop          — COP / efficiency ratio; no backend endpoint
- energyTodayKwh         — backend has total historical kWh, not a "today" counter
- runtimeTodayMinutes    — not in backend
- compressorRuntimeMinutes — not in backend
- airflowM3h             — not in backend
- freshAirRatioPct       — not in backend
- supplyFanSpeedPct      — not in backend
- healthScore            — not in backend
- currentPowerKw (live)  — backend has 5-min historical intervals, not a live reading
- history[]              — per-device minute-resolution telemetry not in backend
- runtimeHeatmap[]       — weekly day/hour runtime heatmap not in backend
- influencingFactors[]   — AI-generated human-readable explanations not in backend
- room.occupancy         — backend has event schedule, not real-time headcount
- room.capacity          — not in backend
- room.forecastOccupancy — not in backend
- room.nextEvent string  — backend has /api/prediction/schedule but not per-room
- room.currentTemperature in 3-D label — backend has snapshots but not wired to label yet
- room.humidityPct       — backend has snapshots but not wired to label yet

── DATA SOURCES REMOVED FROM MOCK (entire objects not in backend) ────────────
- buildingTelemetry[]    — aggregated building-level time series; no backend endpoint
- controlDecisions[]     — automated decision log; no backend endpoint
- plannedActions[]       — ControlTimeline items; no backend endpoint
- roomLoadHeatmap[]      — per-room load % heatmap; no backend endpoint
- weatherForecast.solarWm2 — backend (Open-Meteo) does not return solar irradiance
- Rooms G02, G03, F01, F02, F03 — backend dataset has exactly 1 space (3dbed10b-…)
- roomEvents with expectedStudents — backend /api/spaces/events has start/end,
                                     not student headcount per event

── WHAT THE BACKEND CURRENTLY PROVIDES (available to wire in later) ──────────
/api/devices                → device_id, label, type, hardware_version, position {x,y,z,section}
/api/control/status         → global mode (AUTO/HEAT/COOL/OFF), setpoint_celsius, per-device enabled
/api/impact/summary         → actual_kwh, energy_saved_kwh, cost_saved_eur, co2_saved_kg
/api/impact/by-device       → same, per device
/api/anomaly/alerts         → severity, type, message per device
/api/weather/current        → temperature_2m, relative_humidity_2m, hvac_mode, heating_likely, cooling_likely
/api/weather/forecast       → 7-day hourly: same fields + precipitation, wind, cloud_cover
/api/prediction/schedule    → upcoming event start times with recommended HVAC start
/api/comfort/current        → PMV, PPD, comfort_setpoint, mold_risk
/api/comfort/holidays       → upcoming Bayern Feiertage
/api/devices/<id>/snapshots → room temperature, humidity, CO2, supply/return temps (historical)
/api/devices/<id>/power     → 5-min power draw time series
