## Architectural Decisions

### Common Helper Module
**Decision:** Create a shared helper module at `backend/notebooks/utils.py`.
**Rationale:** Simplifies notebook structure, reduces duplication for dataset loading/alignment, and facilitates maintenance.
**Alternatives Considered:** Fully self-contained notebooks (rejected due to code duplication in loading/cleaning).

### Physical Grey-Box and PINN Modeling
**Decision:** Use SciPy's `minimize` for 2R2C lumped parameter grey-box calibration, and PyTorch for PINNs.
**Rationale:** Enables physically consistent prediction of temperature and integrates heat balance equations into neural model optimization.
**Alternatives Considered:** Black-box ML models only (rejected as they miss the physical constraints).

### PyTorch for Deep Learning
**Decision:** Use PyTorch for the LSTM, PINN, and Autoencoder implementations.
**Rationale:** Standard library for deep learning with easy-to-write custom loss terms (physics residuals).
**Alternatives Considered:** TensorFlow / Keras (PyTorch is preferred for readability and custom gradient computation).

## Error Handling Strategy

- CSV parser checks for file existence and required columns, raising exceptions early if backend data is missing.
- Linear and spline interpolation are used to fill data gaps.
- PyTorch training loops verify model outputs for `NaN` or infinite losses.
- SARIMAX and SciPy optimization steps log convergence status instead of crashing.

## Risks and Unknowns

- **Grey-box Parameter Calibration** — The optimizer might get stuck in local minima during 2R2C parameter estimation.
- **PINN Convergence** — Balancing data loss and physics loss terms might require custom weighting.
