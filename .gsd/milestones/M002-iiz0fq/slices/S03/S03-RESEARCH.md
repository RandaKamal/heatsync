# Research for S03: Baseline vs Smart-Control Comparison, Plots, and CSV Reports

## Context & Objectives
This slice (S03) is the capstone visualization and reporting step for the event-based control optimization built in S01/S02. We need to:
1. Produce heating and cooling validation plots comparing measured-baseline vs smart-control.
2. Calculate and export room temperature with comfort bands, event shading, start times, power comparison, per-device schedules, and cumulative energy.
3. Export time-series CSV reports (`heating_validation_timeseries.csv`, `cooling_validation_timeseries.csv`).
4. Report metrics: electricity (kWh), cost (EUR), CO₂ (kg), comfort (MAE, RMSE, hit rate, degree-minutes violation).
5. Output these into `backend/artifacts/event_device_control/figures/` and `backend/artifacts/event_device_control/reports/`.

## Existing State & Findings
- **S01 & S02 Output**:
  - `backend/artifacts/event_device_control/reports/heating_event_control_results.csv` and `cooling_event_control_results.csv` are already generated by S02 and contain the optimized schedules per event window (or individual events).
  - The results CSV contains columns like `start_time`, `device_1_on`, `device_2_on`, `target_temp`, `predicted_temp_at_start`, `expected_kwh`, `expected_cost`, `expected_co2`, and `feasible`.
- **Notebook & Utils**:
  - `07_event_based_device_control.ipynb` currently executes the optimizer and saves the event results. It does *not* contain the time-series expansion or the final visualization functions.
  - `utils.py` does not currently contain plotting logic or time-series simulation logic for this final step.
- **Constraints & Risks**:
  - *Data Leakage*: The counterfactual smart-control path must strictly use the learned power models and thermal models to predict state from the start of an event pre-conditioning window. It cannot use measured future power or temperatures during the smart-control active periods.
  - *Time-series Generation*: The S02 schedule gives us start times and steady actions for a block. We need to unroll this into a 15-minute grid time-series that merges the baseline data (when not smart-controlling) and the simulated trajectory (when smart-controlling).
  - *Metrics*: Global metrics need to aggregate across the full time-series (or specifically across event windows) to compare baseline vs. smart.

## Implementation Approach
1. **Simulation Unrolling (Time-Series Generation)**:
   - Create a function (likely in `utils.py` or the notebook) that takes the 15-minute aligned baseline data and the optimized schedules (`event_control_results`).
   - Iterate through time: if inside a smart-control window (from `start_time` to event end), use the thermal model to predict temperature and the power model to calculate expected power/energy.
   - If outside the smart window, fallback to baseline values (or simulate drift, but standard approach is usually snapping to baseline or simulating baseline with models, though task says "measured-baseline vs smart-control room temperature", meaning we only simulate where smart control acts).
   - Compute running cumulative energy for both baseline and smart-control.
2. **Metrics Calculation**:
   - Compute RMSE, MAE against the target band during events.
   - Sum energy (kWh), Cost (EUR), CO2 (kg) for baseline (using measured `total_power_kw` * 0.25h) and smart (using simulated `expected_power` * 0.25h).
   - Degree-minutes violation: area outside the comfort band during active events.
3. **Plotting**:
   - Build a comprehensive `matplotlib` figure with multiple subplots (or one rich plot) showing:
     - Top: Temperature (Baseline vs Smart), Comfort bands (shaded area), Event windows (vertical spans/shading).
     - Middle: Total Power (Baseline vs Smart) and Per-device activity lines (gantt-style or step plots).
     - Bottom: Cumulative Energy (Baseline vs Smart).
4. **Notebook Integration**:
   - Add a final section to `07_event_based_device_control.ipynb` that executes this simulation/unrolling and renders the plots for both heating and cooling.
   - Save figures as PNGs to `backend/artifacts/event_device_control/figures/`.
   - Save the unrolled time-series to `reports/{season}_validation_timeseries.csv`.
